# AI-MON — 에이몬

> Python 기초부터 AI 에이전트 구축까지, 캐릭터를 성장시키며 단계적으로 배우는 한국어 중심 게임형 AI 코딩 학습 플랫폼

## 0. 문서 목적

이 문서는 AI-MON의 다음 항목을 정의하는 기획 기준입니다.

- 해결하려는 학습 문제
- 핵심 사용자와 가치
- 현재 구현된 사용자 흐름
- 코스·스테이지·보스 구조
- 성장·보상·랭킹 구조
- 구현 완료·부분 구현·향후 계획
- 다음 기획 우선순위

세부 실행 흐름은 `AI_MON_PIPELINE.md`, 데이터 구조는 `AI_MON_SCHEMA.md`, 미션은 `AI_MON_MISSIONS.md`, 엔드보스는 `ENDBOSS_DESIGN.md`를 따릅니다.

실제 동작이 문서와 충돌하면 GitHub `main` 브랜치의 코드와 데이터가 우선합니다.

## 1. 서비스 정의

### 1-1. 한 줄 정의

AI-MON은 코딩 입문자가 짧은 브리핑, 서버 채점 퀴즈, 보스전, 미니게임을 통해 Python과 AI 개발 역량을 단계적으로 익히는 모바일 중심 웹앱입니다.

### 1-2. 해결하려는 문제

초보 학습자는 다음 지점에서 이탈하기 쉽습니다.

- 긴 강의만으로는 직접 코드를 사용하는 감각을 익히기 어려움
- 반복 문제만으로는 학습 동기가 떨어짐
- 오류가 발생했을 때 원인을 판단하기 어려움
- Python 기초 이후 AI API·LangChain·에이전트 개발로 이어지는 경로가 단절됨
- 점수 외에 성장과 성취가 눈에 보이지 않음

### 1-3. 해결 방식

```text
짧은 개념 브리핑
→ 개념 퀴즈
→ 스테이지 미니보스
→ 유닛 보스
→ 코스 엔드보스
→ 다음 코스 승급과 캐릭터 진화
```

핵심 원칙:

- 짧은 단위로 학습하고 즉시 문제를 풉니다.
- 정답이 결정된 문제는 서버가 직접 채점합니다.
- 자유도가 높은 코드 문제에만 코드 실행 또는 AI 평가를 사용합니다.
- 보스전과 캐릭터 진화로 학습 성과를 시각화합니다.
- 진행도와 보상은 클라이언트가 아니라 서버 기록을 기준으로 검증합니다.

### 1-4. 핵심 사용자

- 코딩 경험이 거의 없는 학생·성인 비전공자
- Python을 처음부터 체계적으로 배우려는 사용자
- Python 이후 AI API와 AI 에이전트까지 연결해 배우려는 사용자
- 강의형보다 짧은 문제와 게임형 진행을 선호하는 사용자

## 2. 브랜드와 성장 경험

사용자는 자신의 AI 캐릭터 에이몬을 학습으로 성장시킵니다.

| 진화 단계 | 캐릭터 | 조건 |
|---:|---|---|
| 0 | 에이원 | 최초 시작 |
| 1 | 에이량 | Beginner 엔드보스 클리어 |
| 2 | 에이훈 | Intermediate 엔드보스 클리어 |
| 3 | 에이왕 | Advanced 엔드보스 클리어 |

진화의 단일 기준은 코스 엔드보스 클리어입니다.
일반 레벨이나 레거시 XP만으로 캐릭터가 진화하지 않습니다.

## 3. 핵심 사용자 흐름

### 3-1. 비로그인 체험

```text
비로그인 랜딩
→ 레슨 탭
→ Unit 1 공개
→ Stage 1-1 브리핑
→ Stage 1-1 개념 퀴즈
→ 80% 이상이면 브라우저에 임시 완료 상태 저장
→ 가입 유도
```

현재 정책:

- 공개 체험 경로는 `/stage/1/1`입니다.
- 비로그인 사용자는 개념 퀴즈까지만 진행합니다.
- 미니보스, 서버 진행도 저장, 보상 지급은 제공하지 않습니다.
- 80% 이상일 때 `localStorage`에 임시 기록합니다.
- 일반 회원가입 완료 후 임시 기록을 서버 진행도로 승계합니다.

현재 한계:

- Google·Kakao·Naver 소셜 가입 콜백에는 동일한 체험 진행도 승계가 아직 연결돼 있지 않습니다.
- 기획 상태는 **부분 구현**입니다.

### 3-2. 일반 회원가입

```text
아이디·이메일·비밀번호 입력
→ 아이디·이메일 중복 확인
→ 이메일 인증코드 발송
→ 인증코드 검증
→ 닉네임 중복 확인
→ 학습 수준·목표·학습 시간 입력
→ 계정 생성
→ 체험 진행도 승계
→ PWA 설치 안내 가능
→ 홈
```

입력 정책:

- 아이디는 영문 소문자·숫자 중심으로 정규화
- 이메일 아이디와 직접입력 도메인은 소문자로 정규화
- 이메일 도메인 드롭다운 제공
- 저장 직전 닉네임 중복 재검사
- 서버는 클라이언트가 보낸 `is_level_tested`를 그대로 신뢰하지 않음

### 3-3. 소셜 로그인

지원 코드 경로:

- Google
- Kakao
- Naver

현재 구현:

- OAuth callback에서 서버 토큰으로 교환
- 신규·기존 사용자를 동일 인증 저장소에 연결
- Google은 인앱브라우저 감지 시 외부 브라우저 안내 표시

운영 확인 필요:

- 공급자별 운영 앱 상태
- redirect URI
- 동의 항목
- 검수·배포 상태
- 체험 진행도 승계
- 프론트 코드의 OAuth Client ID fallback 제거

### 3-4. 로그인 후 학습

```text
로그인
→ 레벨 테스트 또는 선택 코스
→ 코스·유닛·스테이지
→ 브리핑
→ 개념 퀴즈
→ 미니보스
→ 다음 스테이지
→ 유닛 보스
→ 다음 유닛
→ 엔드보스
→ 다음 코스·진화
```

## 5. 학습 구조

### 5-1. 코스

| 코스 | 목표 | 대표 영역 |
|---|---|---|
| Beginner | Python 문법과 기본 문제 해결 | 출력, 변수, 문자열, 조건문, 반복문, 자료구조, 함수 |
| Intermediate | 실용 Python과 구조화된 프로그램 | 예외, 자료형 심화, 함수 심화, OOP, 파일, venv, 정규식, API |
| Advanced | AI 서비스와 에이전트 구축 | 고급문법, 비동기, Claude API, Streamlit, LangChain, FastAPI, 에이전트 |

각 코스는 Unit 1~8로 구성됩니다.

### 5-2. 스테이지 통과 규칙

현재 규칙은 한 개의 퍼센트 기준으로 단순화하지 않습니다.

| 구간 | 현재 기준 |
|---|---|
| 개념 퀴즈에서 미니보스로 진입 | 60% 이상 |
| 스테이지 미니보스 | 5문항 중 4정답 |
| 미니보스 포함 스테이지 완료 | 서버 배틀 세션 승리 |
| 미니보스 데이터가 없는 예외 경로 | 전체 점수 80% 이상 |
| 비로그인 Stage 1-1 체험 | 개념 퀴즈 80% 이상 |

재도전 문제 세트:

```text
1회차: Set A
2회차: Set B
3회차 이상: A+B 혼합
```

### 5-3. 스테이지 미니보스

| 항목 | 규칙 |
|---|---|
| 문제 수 | 5 |
| 승리 | 4정답 |
| 패배 | 2오답 |
| 보상 단위 | 500 |
| 판정 | 서버 배틀 세션 |
| HP | 화면 연출용 |

### 5-4. 유닛 보스

| 항목 | 규칙 |
|---|---|
| 해금 | 해당 유닛의 모든 스테이지 완료 |
| 승리 | 정답 5회 |
| 패배 | 오답 3회 |
| 무료 도전 | 하루 2회 |
| 추가 도전 | 왕관 1개 |
| 힌트 | 최대 2회 |
| 보상 단위 | 3,000 |
| 판정 | 서버 배틀 세션 |

### 5-5. 엔드보스

```text
Phase 1: 코드 분석 5문제
→ Phase 2: 디버깅·코드 완성 4문제
→ Phase 3: 결정타, 최대 3회
```

| 항목 | 규칙 |
|---|---|
| 코스 | Beginner / Intermediate / Advanced |
| 프로젝트 | 코스별 4개 |
| 비용 | 왕관 3개 |
| 최초 보상 | 코인 15,000 + 누적 랭킹점수 15,000 + 왕관 15 |
| 추가 보상 | 코스 칭호 + 진화 + 다음 코스 승급 |

세부 상수와 문제 풀은 `ENDBOSS_DESIGN.md`와 실제 라우터·JSON을 기준으로 합니다.

## 6. 채점과 AI

### 6-1. 채점 방식

| 유형 | 기본 채점 |
|---|---|
| `multiple_choice` | 서버 정답 비교 |
| `output_select` | 서버 정답 비교 |
| `error_find` | 서버 정답 비교 |
| `fill_in_blank` | 서버 비교·정규화 |
| `code_input` | 코드 실행·결정론적 채점 또는 Claude 평가 |
| `code_multi_input` | 슬롯별 채점 |

정답, 해설, 힌트는 문제 조회 응답에서 제거합니다.

### 6-2. AI 사용 범위

Claude는 다음처럼 직접 비교가 어려운 영역에 제한적으로 사용합니다.

- 자유도가 높은 코드 작성 문제
- 학습 레벨별 맞춤 오답 설명
- 유닛 보스 힌트
- 고급 코드의 구조·예외·확장성 평가

객관식 계열 오답은 LLM 없이 즉시 정적 피드백을 반환합니다.

현재 사용 모델 기준:

```text
claude-haiku-4-5-20251001
```

## 7. 성장·재화·랭킹

### 7-1. 역할 분리

| 필드 | 역할 | 소비 |
|---|---|---:|
| `coin_balance` | 상점·테마 구매 | 가능 |
| `total_coin_earned` | 누적 획득 기록 | 불가 |
| `ranking_score` | 전체 누적 경쟁 점수 | 불가 |
| `weekly_ranking_score` 및 게임 기록 | 주간 경쟁 | 불가 |
| `gp` | 최종 진화 후 성장 | 불가 |
| `crowns` | 보스 도전·힌트·챌린지 | 가능 |
| `xp` | 하위 호환 레거시 | 신규 기준 아님 |

### 7-2. 주요 보상

| 활동 | 코인 | 누적 랭킹 | GP |
|---|---:|---:|---:|
| 스테이지 최초 완료 | 2,000 | 2,000 | 최종 진화 후 2,000 |
| 미니보스 최초 클리어 | 500 | 500 | 최종 진화 후 500 |
| 유닛 보스 최초 클리어 | 3,000 | 3,000 | 최종 진화 후 3,000 |
| 엔드보스 최초 클리어 | 15,000 | 15,000 | 0 |
| 미션 | 정의별 | 코인과 같은 값 | 0 |
| 미니게임 | 결과별 | 결과별 | 최종 진화 후 정책값 |

최초 클리어와 토큰 소비는 서버에서 중복 차단합니다.

## 8. 미션과 미니게임

### 8-1. 미션

| 구분 | 현재 미션 |
|---|---|
| Daily | 스테이지 3회, 오답 복습 1회, 출석 |
| Weekly | 보스 2회, 주 5일 출석, AI 피드백 5회 |

모든 미션 보상은 사용자가 직접 수령합니다.

### 8-2. 미니게임

| 게임 | ID | 핵심 플레이 |
|---|---|---|
| 에이팡 | `aipang` | 3매치 퍼즐 |
| 에이짝 | `aizzak` / route `pairs` | 카드 짝 맞추기 |
| 에이런 | `runner` | 3D OX 러닝 |
| 에이밤 | `aibomb` | 코드 오류 찾기 |
| 에이칸 | `aicross` | 서버 채점 십자말풀이 |

게임 보상은 서명 토큰, nonce, 최소 플레이 시간, 점수 범위, 일일 횟수로 검증합니다.

랭킹:

- 누적 종합 랭킹: `ranking_score`
- 주간 미니게임 랭킹: ISO 주차별 게임 점수
- 조회 캐시: 30초 TTL
- 현재 게임별 가중치: 1.0
- 실제 분포가 쌓인 뒤 계수 조정

## 9. PWA

현재 코드 구현:

- 자동 서비스 워커 등록·업데이트
- standalone manifest
- portrait 방향
- 192·512·maskable 아이콘
- 일반 회원가입 완료 후 설치 안내
- 설치 여부 감지
- 거절 횟수별 재안내 간격

거절 정책:

```text
1회: 7일 후
2회: 30일 후
3회: 자동 안내 중단
```

부분 구현·운영 확인:

- iOS Safari는 `beforeinstallprompt`를 지원하지 않아 별도 수동 설치 안내가 필요함
- 배포 후 아이콘·캐시·업데이트·오프라인 범위를 실제 기기에서 확인해야 함
